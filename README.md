# NEXUS: 4D

> 你看到的，只是这个世界的一个切面。

一款运行在桌面浏览器中的高维空间解谜游戏。玩家旋转一个真实的四维超立方体（tesseract），观察它在三维空间中的投影如何变形、交叠、重组，并利用这些变化接通断桥、显露隐藏节点、抵达传送门。

**四维旋转与投影是真实计算的**；关卡中的可行走表面与通关条件由明确、可测试的游戏规则控制。这是有意的工程取舍：做一个数学正确的解谜系统，而不是一个完整的四维物理引擎。

完整游戏规划为 **一周七章** 的游玩流程（每章约一个游玩日，引入一个新的高维概念）。**三天开发的 MVP = 第一章（三关）**，其余六章为内容路线图。

- 平台：桌面浏览器（Chrome / Edge / Firefox 最新版），键盘 + 鼠标
- 技术栈：Vite + React + TypeScript + Three.js（原生，不用 R3F）+ Vitest
- 不做：多人、账号、存档云同步、移动端、程序化关卡、完整四维碰撞

## 1. 核心体验

| 机制 | 说明 |
|---|---|
| **四维旋转** | 六个独立旋转平面：XY、XZ、YZ（熟悉的三维旋转）与 XW、YW、ZW（跨入第四维）。后三者无法用任何三维旋转替代。 |
| **三维投影** | 四维顶点经透视投影落入三维场景。改变 W 相关角度时，内立方体与外立方体会真实地交换、膨胀、收缩。 |
| **空间解谜** | 旋转结构让投影节点与世界锚点对齐 → 能量桥生成；调整 W 切片让隐藏节点浮现 → 新路径出现。 |
| **切片** | 用三维超平面 `w = w₀` 切开超立方体，展示截面线框：从一个点长成立方体，再缩回一个点。 |

一句话的"惊艳时刻"：玩家转动 XW，眼前的几何结构缓缓翻转，断桥两端在空中相遇，桥亮起，玩家走过去。

## 2. 输入与职责划分

**一个输入只做一件事。** 四维物体的旋转状态与观察摄像机的状态是两个独立对象，永不共用。

| 输入 | 作用 |
|---|---|
| `W A S D` / 方向键 | 角色在可行走表面上移动 |
| 鼠标左键拖动 | **摄像机**轨道旋转（OrbitControls，目标为关卡中心） |
| 鼠标滚轮 | 摄像机缩放 |
| `Q` / `E` | 四维核心 **XW** 平面旋转 −/+ |
| `Z` / `C` | 四维核心 **YW** 平面旋转 −/+ |
| `1`–`6` | 选择当前"自由平面"（XY / XZ / YZ / XW / YW / ZW） |
| `[` / `]` | 当前自由平面旋转 −/+ |
| `,` / `.` | W 切片位置 −/+（第三关起启用） |
| `X` | 显示 / 隐藏切片截面（仅启用切片的关卡） |
| `R` | 重置当前关卡的四维状态与角色位置 |
| `Esc` | 暂停 / 继续 |
| `M` | 静音（记忆在 localStorage） |
| `B` | 开关 bloom 发光后处理（低端机可关） |
| `Shift + [ ]` | 等角双旋：关卡定义的一对正交平面同速旋转（第二章） |
| `P` | 透视 ⇄ 正交投影切换，0.45 s 过渡（第四章） |
| `` ` `` | 调试面板（直接拖动六个平面与切片） |

**磁性吸附**：当目标顶点接近锚点（共振度 > 70%）时，四维旋转速度平滑降到最低 30%，避免低帧率下"一帧跳过共振窗口"。

HUD 始终显示：六个平面的当前角度、当前自由平面、切片位置、桥接条件的实时满足情况。

## 3. 四维数学

全部实现位于 `src/math/`，**不依赖 Three.js**，可独立单元测试。

### 3.1 超立方体

16 个顶点 `(x, y, z, w)`，每个坐标 ∈ {−1, +1}。两顶点**恰好一个坐标不同**则连边 → 32 条边。24 个正方形面由"固定两个坐标、另两个坐标自由"枚举生成。顶点、边、面都是程序生成的，不硬编码。

### 3.2 旋转

通用函数 `rotate4D(v, plane, θ)`。以 XW 平面为例：

```
x' = x·cosθ − w·sinθ
w' = x·sinθ + w·cosθ
```

其余平面只替换参与的两个坐标。六个角度组成的状态 `Rotation4D` 按固定顺序 **XW → YW → ZW → XY → XZ → YZ** 依次应用，保证确定性。W 平面在前、三维平面在后是有意的：三维平面只混合 x/y/z，作用在 W 旋转之后，**在任何状态下都不改变顶点的 w**（见 3.5）。

### 3.3 投影

透视投影，投影距离 `d`（默认 3）：

```
s = d / (d − w)
(x₃, y₃, z₃) = s · (x, y, z)
```

分母 `d − w` 钳位到最小值 `ε = 0.05`，避免 NaN / Infinity / 几何爆炸。

### 3.4 切片

超平面 `w = w₀`。对每条边 `(a, b)`：若 `(a.w − w₀)(b.w − w₀) < 0`，交点为 `a + t·(b − a)`，`t = (w₀ − a.w)/(b.w − a.w)`。
对每个正方形面取其四条边的交点（0 或 2 个），两点连成线段 → 截面线框。截面以同样的透视投影送入场景。

### 3.5 关键数学事实（关卡设计依赖）

- 对未旋转的超立方体，顶点 w = ±1，投影后半径分别为 **内立方体 `d/(d+1)`** 与 **外立方体 `d/(d−1)`**（d = 3 时为 0.75 与 1.5）。
- **XY / XZ / YZ 旋转不改变任何顶点的 w**（由应用顺序保证，对任意当前姿态成立），因此只等价于把投影整体做三维旋转：每个顶点只能在自己的球面上移动。
- **只有 XW / YW / ZW 旋转能改变 w**，从而改变投影半径。
- **正交投影下对径顶点 v 与 −v 的影子永远中心对称**（丢掉 w 后 −v 的坐标就是 v 的相反数，对任意姿态成立）；**透视投影下只有 w = 0 时对径顶点才等距**（半径比 = (d+w)/(d−w)）。因此"两个锚点等距反向"只有正交做得到、"一近一远"只有透视做得到——这是第四章的根据。
- **截面形状只取决于"什么朝着 W"**（第三章依赖）：设 k 为非零的 W 平面旋转个数（XW/YW/ZW 中），则切片 `w = w₀` 的截面：k = 0 → 立方体；k = 1 → **永远是长方体**（最前端是一个面，旋转只改变比例）；k = 2 → 最前端是一条棱，截面在三棱柱 / 五棱柱 / 六棱柱之间变化；k = 3 → 最前端是一个顶点，顶点附近是四面体，中段是十二顶点体（截角四面体 ↔ 六棱柱），正八面体只在"顶点朝前"的精确姿态正中出现（测度为零，不可作为关卡目标）。纯三维旋转不改变截面签名。

→ 把锚点放在半径 `r_anchor ∈ (d/(d+1), d/(d−1))` 上（默认 1.1），则**数学上保证**纯三维旋转无法对齐，必须使用 W 旋转。这是第一关"试试 W"教学可靠成立的根据，不依赖任何角度范围补丁。

## 4. 解谜规则

### 4.1 桥接条件

一座桥由 `{ 锚点 anchor（世界坐标，固定）, 目标顶点 vertexIndex（超立方体顶点）, 出口方向 exitDir }` 定义。每帧计算：

| 条件 | 默认阈值 |
|---|---|
| 距离：`|project(vertex) − anchor| < δ` | δ = 0.18 |
| 方向：`angle(project(vertex) − bridgeStart, exitDir) < α` | α = 12° |
| 持续时间：上述条件连续满足 | 300 ms |

进度条在 HUD 中可见（0–300 ms 填充），给玩家"快对了"的反馈。

### 4.2 锁定规则

桥一旦激活即**锁定**，之后旋转核心不会断开它。理由：避免玩家站在桥上误操作坠落的挫败感，并把"激活"作为明确的成功反馈。`R` 重置会解除锁定。

### 4.3 可行走表面

可行走区域 = 静态平台 AABB 集合 ∪ 已激活桥的 AABB。角色移动按 XZ 平面处理，每帧检测目标位置是否落在任一 AABB 内；不在则阻止移动（不做重力与坠落）。桥激活后其 AABB 立即加入集合，**不存在"桥亮了但走不过去"的状态**。

### 4.4 节点

节点 `{ 位置, 半径, 激活条件 }`。激活条件可以是：桥接条件（同 4.1）、切片位置落在区间内、或前置节点已激活。节点激活触发关卡事件（开启下一座桥、显示提示、解锁出口）。

### 4.5 出口

出口传送门在关卡所有必需节点激活后可用；角色进入出口半径 → 关卡完成 → 播放四维翻转过场 → 下一关。

## 5. 一周游玩流程（七章）

每章 3–5 关，约 20–40 分钟，恰好一个"游玩日"。每章只引入**一个**新概念，并在章末用一个综合关卡验收。玩家一周走完，就从"看见四维投影"走到"在四维中移动"。

| 日 | 章节 | 新概念 | 玩家学会什么 | 典型谜题 |
|---|---|---|---|---|
| **Day 1** | **The Fold 折叠** | XW / YW / ZW 单平面旋转、透视投影、W 切片 | W 旋转会让投影变形，内外立方体交换；切片能显露隐藏结构 | 断桥对齐、两阶段连接、切片显露节点 **（MVP）** |
| **Day 2** | **Double Rotation 双旋** | 两个完全正交的平面同时旋转（XW + YZ、YW + XZ、ZW + XY） | 四维里存在三维没有的"双旋转"：物体没有任何固定轴 | 双旋桥：两个目标同时到位；等角双旋让所有顶点同速绕行 **（已实现）** |
| Day 3 | Cross-Sections 截面 | 旋转后的切片 | 同一个超立方体，切面可以是立方体、三棱柱、四面体、八面体式的截面 | 让截面变成指定形状以匹配平台轮廓；移动切片位置"扫描"出一条通路 |
| Day 4 | Shadows 投影之辨 | 正交投影 vs 透视投影，可切换 | 投影不是物体本身；不同投影方式揭示不同信息 | 一个锚点只在正交投影下可达，另一个只在透视下可达；利用投影切换"搬运"节点 |
| Day 5 | Other Polytopes 异形 | 16-cell（正十六胞体）、24-cell | 四维里有六种正多胞体，各有不同的投影与截面行为 | 16-cell 的截面是八面体；用 24-cell 的高对称性做多锚点同时对齐 |
| Day 6 | Crossing Over 跨越 | **玩家自身获得 W 坐标** | 平台可以存在于不同的 w 层；在三维里"不相连"的平台，沿 W 移动即可到达 | 沿 W 滑动穿过墙壁；在 w 不同的两个房间之间"折叠"过去；敌对结构只存在于某个 w 层 |
| Day 7 | The Nexus 枢纽 | 综合 | 所有机制 | 终章：一个大型超立方体迷宫，需要旋转、切片、换投影、换 W 层协同；通关后展示玩家整段路径在四维中的轨迹 |

### 概念递进原则

- Day 1–3 玩家**只操控物体**，自己始终在三维里；Day 4–5 扩展"观察方式"和"对象种类"；Day 6 才让玩家自身进入四维。这样每一次能力扩展都有前面三章的直觉铺垫。
- 每章末关不引入新概念，只做组合。
- 任何一章都可以单独砍掉而不破坏前后衔接（Day 4 和 Day 5 优先级最低）。

### 章节对系统的要求（路线图）

| 章 | 需要新增的系统 |

| Day 2 | **已实现**：双旋桥（两个目标同时到位）、面心目标、投影后视角倾斜 `tilt`、等角双旋输入（Shift + [ ]）、章节结构与选章 |

## 6. MVP 关卡设计（第一章）

### Level 01 — The Fold（折叠之门）

**教学目标**：理解"W 旋转改变投影"并亲眼看见断桥接通。

```
[起点平台] ──断口── [出口平台 ◎传送门]
              ↑
         四维核心（悬浮于断口上方）
```

1. 玩家出生于起点平台，看到前方断开的桥和清晰可见的出口。
2. 玩家拖动鼠标只会转动摄像机；按 `1`–`3` + `[` `]` 旋转 XY/XZ/YZ，核心会转，但桥不会接通（见 3.5，数学保证）。
3. 尝试三维旋转约 5 秒后，提示出现：**"你只旋转了熟悉的三个维度。试试 W。"** 同时 `Q / E` 键位高亮。
4. 按住 `Q / E`，内外立方体开始交换；目标顶点轨迹掠过锚点；HUD 进度条填充；桥亮起并锁定。
5. 走过桥，进入传送门。过场动画：摄像机拉远，核心做一次完整的 XW 翻转。

**通关条件**：桥 #1 激活 ∧ 角色进入出口。预期时长 2–3 分钟。

### Level 02 — Reassembly（重组）

**目标**：两阶段连接，引入第二个 W 平面。

```
[起点] ──桥A── [中继平台 ●节点] ──桥B── [出口]
```

- 桥 A 由 XW 旋转激活（巩固第一关）。
- 中继节点需要角色**站上去**才激活（空间上的"到达"而非旋转）。
- 节点激活后桥 B 的锚点出现；桥 B 要求 **YW** 旋转（`Z / C`），且目标顶点与桥 A 不同，因此桥 A 的解不会顺带满足桥 B。
- 桥 A 已锁定，所以玩家可以放心旋转 YW。

**通关条件**：桥 A 激活 ∧ 节点激活 ∧ 桥 B 激活 ∧ 进入出口。

### Level 03 — The Slice（切面）

**目标**：引入 W 切片，理解"同一个物体在不同切面上是不同形状"。

```
[起点] ──桥A── [平台 ▣隐藏节点] ──桥B── [出口]
```

- 场景中同时显示投影线框（半透明）与 **切片截面**（实线、高亮）。
- 隐藏节点只在切片位置 `w₀ ∈ [0.3, 0.5]` 时在截面上显现（截面线框的一个顶点落到节点位置），停留 300 ms 激活。节点显现前 HUD 只显示"—"，不泄露位置。
- 切片初始 `w₀ = −0.9`（可见一个立方体截面），范围 `[−2.2, 2.2]`。
- 节点激活后自动把自由平面切到 **ZW**，HUD 同步提示 `6` + `[ ]`。
- 节点激活后桥 B 的锚点出现，要求 **ZW** 旋转（自由平面 `6`）。
- 桥 A 为普通 XW 桥，开局即可解，作为热身。

**通关条件**：桥 A ∧ 切片节点 ∧ 桥 B ∧ 进入出口。完成后进入最终结算界面。

## 6b. 第二章关卡设计（Double Rotation 双旋）

**设计约束（从失败里学到的）**：最初用两个*顶点*做双旋桥（XW + YW），两个目标对两个平面的敏感度几乎相同（每个顶点的 |x| = |y| = 1），玩家交替调两个旋钮会来回震荡，无头浏览器里的贪心机器人 6 轮都收敛不了。解决办法有两条，都写进了引擎：

1. **只用完全正交的平面对**（XW+YZ、YW+XZ、ZW+XY）。它们的旋转可交换，这才是数学上的"双旋转"。
2. **目标用"面心"而不是顶点**：`(±1,0,0,±1)` 这种面心只被 XW 移动、对 YZ 完全不动；`(0,±1,±1,0)` 反之。两只手严格解耦（有测试断言 `< 1e-9`）。
3. 基础姿态必须是单位元，否则固定旋转顺序里的 XY/XZ 会把 x 混进 y、z，破坏解耦。视角用 **`core.tilt`（投影后的三维倾斜，pitch/yaw）** 来摆，与四维姿态无关。
4. 面心的三维半径随 XW 变化很小，为了保证"纯三维旋转不可解"，解角要选在 ±65° / ±110° 这类让半径差 > 0.45 的位置，锚点半径 > 0.9 保持可辨。

### Level 04 — Two Hands（双手）
- 一座双旋桥 `XW + YZ`：目标 1 面心 `(−1,0,0,1)` 解 XW = −65°；目标 2 面心 `(0,1,−1,0)` 解 YZ = −110°。
- HUD 显示两条距离条（`距离XW`、`距离YZ`），各自只响应一个平面。
- 通关：两个目标同时在容差内 300 ms → 锁定两个平面。

### Level 05 — Isoclinic（等角）
- `core.linked = ['XW','YZ']`：按住 **Shift + [ ]**，两个平面以相同角速度一起转。
- 目标是两个顶点（4 与 14），解 XW = YZ = +100°。顶点目标是耦合的，所以分开调很难，等角一个旋钮就到 —— 这就是教学点。

### Level 06 — Counterweight（配重，章末综合）
- 桥 A：面心双手桥 `YW + XZ`（Z / C 与 2 + [ ]），解 YW = +65°、XZ = −85°。
- 中继节点（到达触发）→ 桥 B：等角双旋 `ZW ≡ XY`（Shift + [ ]），顶点 10 与 12，解 +100°。
- 完成后进入第二章结算，主菜单的章节卡标记"已通关"（localStorage）。

## 6c. 第三章关卡设计（Cross-Sections 截面）

**概念**：同一个超立方体，不同朝向给出不同形状的三维截面。玩家用 W 旋转改变"哪一端朝着 W"，再用 `, .` 移动切片位置 `w₀` 去"扫描"。
**机制**：本章没有锚点桥。新增两种元素：
- **形状节点** `trigger: { kind: 'shape', shape: { vertices, edges }, holdSeconds }`：当前截面签名匹配并保持 0.5 s 即激活；HUD 显示"保持 xx%"。
- **闸门** `gates[]`：`requires` 中的节点全部激活即成为可行走路面（金色，从 `start` 一侧生长），没有插座、不需要锁定。
HUD 左栏新增"截面"行：实时显示截面名称与 `v · e · f`。切片在核心之外时显示"空"。

### Level 07 — Prism（棱柱）
- 闸门要求 **三棱柱 6v · 9e**。初始姿态为单位阵，w₀ = 0，截面是正立方体。
- 教学点：只转一个 W 平面，无论怎么转截面都是长方体 → 提示 `noW:8` 引导"同时转两个"。解：YW ≈ 40° + ZW ≈ 30°，w₀ 推到 |w₀| ≳ 0.75。

### Level 08 — Vertex First（顶点朝前）
- 闸门要求 **四面体 4v · 6e**：必须三个 W 平面都非零，并把 w₀ 推到顶点附近（|w₀| ≳ 1.2）。
- 类比：立方体顶角附近的截面是三角形。

### Level 09 — Scan（扫描，章末综合）
- 三个形状节点按顺序：三棱柱（→ 闸门 A）→ 四面体 → 十二顶点 12v · 18e（→ 闸门 B → 出口）。
- 最后一步要求保持三个旋转、把 w₀ 从顶点扫回正中：玩家亲眼看到截面经过三棱柱、长方体、五棱柱变成十二顶点体——这就是"用三维切片扫描四维"。

### 踩坑记录（第三章）
1. **单个 W 旋转永远不改变截面形状**，只改变比例——早期想用"XW 转到某角度得到三棱柱"做关卡，数学上不可能。
2. 三个 W 平面的一般姿态下，6v/8v/10v 的 w₀ 带宽只有 0.02–0.2，不能当目标；只用两端的四面体和中段的十二顶点体。
3. 正八面体只在精确姿态的 w₀ = 0 出现，HUD 会报名字但不作为任何关卡目标。
4. 中段 12v18e 的面型会在 `3,3,3,3,6,6,6,6`（截角四面体）与 `4×6,6,6`（六棱柱）之间连续变化（如 `3,3,3,4,4,5,6,6`），命名时统一退化为"十二顶点体"，形状要求只比较顶点/边数。

## 6d. 第四章关卡设计（Shadows 投影之辨）

**概念**：投影不是物体本身。同一个四维姿态，透视与正交给出不同的影子，各揭示一半信息。
**机制**：`core.projection = { initial, switchable }`，P 键切换，`projectionBlend` 以 0.45 s 在两种投影间线性过渡（渲染与判定都用混合后的位置）。`BridgeDef.projection` 指定锚点在哪种投影下求得；判定永远用玩家当前投影 → 投影不对，怎么转都够不着。本章每座桥都是一对**对径顶点**（v, −v），只用一个平面。

### Level 10 — Shadow（影子）
- 开局**正交**：十六个顶点两两重合，核心看起来只是立方体。锚点 = 顶点 0 / 15 在透视、XW = −110° 下的位置：一近一远。
- 正交下对径顶点永远等距 → 无解（扫遍 XW 最小距离 1.27）。切到透视后 XW 一个平面即可。

### Level 11 — Silhouette（剪影）
- 开局**透视**：锚点 = 顶点 1 / 14 在正交、YW = 60° 下的位置：等距反向。
- 透视下对径顶点等距只在 w = 0（半径 2）出现 → 无解（最小距离 1.26）。切到正交后 YW 即可（正交下 YW = −150° 也是解，影子相同）。

### Level 12 — Two Truths（两种真相，章末综合）
- 桥 A：透视 · XW = −110°（0 / 15）→ 中继节点 → 桥 B：正交 · YW = 60°（1 / 14，解含已锁定的 XW）。开局正交。
- 玩家需要在同一关内两次换灯：先透视、后正交。

### 踩坑记录（第四章）
1. 一开始想用"半径"区分两种投影——但只要允许三个 W 平面，透视与正交都能把顶点半径放到 [0, 2] 的任何值，无法区分。真正的不变量是**对称性**（见 §3.5）。
2. 对径顶点对在同一平面上强耦合，不能复用第二章"双旋桥：单平面不可解"的测试；改为"在另一种投影下任意角度不可解"的测试。
3. 过渡动画期间 blend ∈ (0,1)，两个目标不会同时满足（已测试），所以不会在切换瞬间误锁。

## 6e. 第五章关卡设计（Other Polytopes 异形）

**概念**：四维有六种正多胞体；超立方体不是全部。本章用两种：
- **正十六胞体**（16-cell，超立方体的对偶）：8 顶点 / 24 边 / 32 三角面 / 16 四面体胞。顶点正对 W 时**每个**截面都是正八面体（超立方体胞正对 W 时每个截面都是立方体——对偶的镜像）。顶点形也是八面体，所以任何姿态顶端附近都是八面体；只有"正中也是八面体"才能证明顶点正对 W。
- **正二十四胞体**（24-cell，自对偶，无三维类比）：24 顶点 / 96 边 / 96 三角面 / 24 正八面体胞。胞正对 W（单位姿态，e₄ 是胞心）时截面是**截角八面体** 24v36e；顶点正对 W（XW 45°）时顶端附近是**立方体**（顶点形）。对称群 1152 阶。

**系统**：`Polytope4` 的 `Face` 改为任意多边形、新增 `cells`（面下标集合），`sliceHyperplane` / `sectionSignature` 对三种多胞体一视同仁；`core.polytope` 指定核心（GameController 在换关时重建线框）；`BridgeDef.anyVertex`（任意顶点可填锚点，取最近者）；形状节点 `w0Range`。

### Level 13 — Sixteen（十六胞体）
- 开局 XW 30° / YW 20°，w₀ = 0.2：正中截面是立方八面体；顶端是八面体但 |w₀| 不在 [−0.2, 0.2]。
- 节点要求"正中八面体"（|w₀| ≤ 0.2）→ 把 XW、YW 转回 0°（或 ±90°、180°：另一个顶点正对 W，同样可解）。

### Level 14 — Twenty-Four（二十四胞体）
- 开局单位姿态（胞正对 W），截面是截角八面体；只允许 XW。节点要求立方体 8v12e → XW ≈ 45° 并把 w₀ 推到顶端（立方体带约 [0.75, 1.4]，角度容差宽，30°–55° 都有带）。

### Level 15 — Symmetry（对称，章末综合）
- 立方体截面 → 闸门 A → 中继 → **任意顶点**双旋桥（XW −75°、YZ 70°，顶点 (1,0,0,1) 与 (0,1,1,0) 的位置，但任何顶点落上去都算）→ 出口。
- YZ 多转 90° 仍是解（另一个顶点落到锚点）；45° 不是。纯三维旋转最小距离 0.289 > 1.5 × 容差。

### 踩坑记录（第五章）
1. 16-cell / 24-cell 有大量顶点恰好落在 w = 0 上；切片用严格穿越判定，在 w₀ 恰为 0 时会丢掉这些顶点得到退化签名。关卡把初始 w₀ 设为 0.2 / 0.3，形状判定避开精确 0。
2. 任意顶点桥不能复用"纯三维旋转够不着"的强下界——24 个顶点总有一个离锚点不远。靠搜索挑解角，要求最小距离 > 1.5 × 容差。
3. 章末关若先锁桥再要"顶点正对 W"的截面，锁定的平面会让顶点正对 W 变得不可能；所以顺序是**先截面、后桥**。

## 6f. 第六章关卡设计（Crossing Over 跨越）

**概念**：前五章玩家只转动四维物体，自己始终在三维里。本章玩家自身获得 **w 坐标**：平台可以位于不同的 w 层（`AABB.w`，默认 0），|玩家 w − 平台 w| ≤ 0.5 才算同层、才能行走。按 **I / K** 沿 W 滑动（1.4 w/s），只能滑到脚下仍有同层地面的位置：`slideW` 按 4 个小步推进并逐步检查脚印，所以**不可能跳过中间层**；松手后 `settleW` 把 w 回弹到最近的层中心（像弹簧一样提示"那边没有地面"）。三维里"不相连"的两块平台，经由另一个 w 层连起来。

**系统**：`AABB.w`、`W_LAYER_HALF = 0.5`、`boxesAtW`、`slideW` / `nearestLayer` / `settleW`（纯函数，在 `puzzle/PuzzleRules.ts`）、`PuzzleSession.walkableAt(w)` / `isWalkable(p, margin, w)`、`PuzzleFrameInput.playerW`、`reach` 节点与出口的 `w`、`LevelDef.playerW { enabled, initial, range, sliceFollows }`。`sliceFollows` 为真时 `CoreController.sliceFollowsPlayer` 禁用 `, .` 与 `X`，每帧 `slice.w0 = player.w`。HUD 新增"你的 w"仪表（紫 = +，金 = −，脚下无地面时提示）；角色随 w 着色；`LevelView` 中非当前层的平台只画按 w 着色的淡轮廓并沿 Y 微微错开，当前层实体显示。

### Level 16 — Step Aside（侧步）
- w = 0 两块平台中间有缺口；w = +1 一条走廊横跨缺口，只与两端平台重叠一小段。无旋转、无桥：站到重叠处按 I → 沿走廊走 → 按 K 回到 w = 0。在起点后端按 I 会被挡在 0.5 并回弹。

### Level 17 — Through（穿过）
- 起点 → w = +1 走廊 → 中间平台（w = 0）。桥的钥匙节点在 **w = −1**（中间平台正下方的"暗室"），`reach` 节点带 `w: -1`，站在 w = 0 的同一位置不会触发。回到 w = 0 后用 XW 110°（顶点 1）锁桥 → 出口（w = 0）。

### Level 18 — You Are the Slice（你就是切片，章末综合）
- `sliceFollows`：切片 w₀ 就是玩家 w。起点三层叠放（w 0/1/2），对岸同样三层。三个 W 平面转到 XW 35° / YW 40° / ZW 30° 后，沿 W 向上爬——经过 |w₀| ∈ [1.22, 1.98] 时截面是四面体（`holdSeconds: 0.2`，边滑边扫就能触发）→ 闸门（w = 2）开 → 走过去 → 逐层下到 w = 0 → 截面十二顶点 → 出口。

### 踩坑记录（第六章）
1. 方向键已用于行走，W 移动用 I / K。
2. "同层 = 半层带"意味着在任意平台上都能把 w 挪到 ±0.5；若不回弹，玩家会停在层与层之间、仪表与着色都很怪。加了 `settleW`（2.8 w/s）后松手即回到层中心，但这也意味着**形状节点不能要求玩家停在层间**——L18 的四面体节点改为短 hold（0.2 s），边滑边扫。
3. 垂直堆叠必须包含每一个中间层（0 → 2 必须有 1），否则 `slideW` 会挡在 0.5。
4. L17 的桥要通过"纯三维旋转够不着"的测试：XW −100° / 顶点 5 的锚点半径不够远（最小距离 0.175 < 0.27），改用顶点 1 / XW 110°（1.139）。
5. `PlayerController` 依赖 `document`（角色贴图），不能在 Vitest 里构造，所以沿 W 的逻辑抽成纯函数 `slideW` / `settleW` 放进 `puzzle/`，测试直接打纯函数。

## 6g. 第七章关卡设计（The Nexus 枢纽）

**概念**：没有新概念。前六天的每一种能力各自回响一次，然后在枢纽里同时用上。通关后展示玩家在枢纽里的整段四维轨迹。

**系统**：`src/puzzle/trail.ts`——`Trail`（按最小步长 0.15 / Δw 0.05 采样 (x, y, z, w, t)）、`trailStats`（路程、沿 W 位移、经过的层数、时长）、`trailTopDown`（俯视图等比映射）、`trailWProfile`（W 剖面，横轴 = 归一化路程）、`trailColor`（w → 青/紫/金）。`GameController` 每帧 `trail.push`，只在 complete / won 阶段把轨迹放进快照；`Victory` 在最后一章渲染 `TrailMap`（SVG：路径按 w 着色、起点实心青点、终点金环，下方 W 剖面与统计）。HUD 桥标签改为"双旋 / 对径 / 透视 / 正交"按实际属性组合。

### Level 19 — Echo（回响）
- 第二章双旋桥（XW −65° / YZ −110°，面心目标，基础姿态必须是单位姿态 + tilt）→ 对岸节点要三棱柱：XW/YZ 已锁，只剩 YW，±20°–40° 加 |w₀| ≈ 1–1.5 就是三棱柱带 → w = +1 的回声室闸门 → I 上去碰节点 → K 下来 → 出口（w = 0）。

### Level 20 — Two Lights（两盏灯）
- 24-cell、透视/正交可切。立方体截面（XW ≈ 45°、w₀ 推到顶端）→ 闸门 → 中间平台下 w = −1 的钥匙 → 任意顶点双旋桥 **只在正交投影下可解**（XW −105° / YZ 70°；透视下同角度不满足，纯三维旋转最小距离 0.351 > 0.27）。

### Level 21 — The Nexus（枢纽，终章）
- 中央 5×5 平台 + 四条辐条，顺序不限但互相解锁：
  - **北**：双旋桥（XW −65° / YZ −110°）→ n-node。
  - **西**：五棱柱 10v · 15e 截面（只有北桥锁定后、再转 YW ±20°–30°、|w₀| ≤ 0.6 才有；锁定前任何 YW 都找不到）→ 西闸门 → w-node。
  - **东**：w = +1 走廊（x 1–6）从中央平台铺到东平台，e-node 在东平台下方 w = −1 的小室——同一位置三层。
  - **南**：三个节点点亮后出现，**正交投影下的 YW/ZW 双旋桥**（YW −75° / ZW −45°，顶点 8 与 1；透视下单独扫任一平面都不满足；纯三维旋转最小距离 2.14）→ 出口。
- 辐条桥面 / 闸门 / 走廊都加宽到 ±1.0，比前面关卡的 ±0.7 宽松——终章不该卡在走位上。

### 踩坑记录（第七章）
1. 面心双旋桥的"严格解耦"测试要求基础姿态是单位姿态（XZ 0.3 的倾斜会让目标 1 随第二平面变化），L19/L21 改用 `rot({})` + `tilt`。
2. 南桥最初设计为对径顶点 (1, 14) 的单平面 YW 正交桥；在北桥锁定后的姿态下，YW 任何角度在透视下都能被满足（"另一种投影下无解"测试过不了）。改为 YW/ZW 两个平面各一个顶点的双旋 + 正交，用脚本按测试条件（单平面不可解、另一种投影不可解、纯三维下界、锚点间距）全量扫描，12984 组候选里取最稳的一组。
3. L20 把 L15 的桥直接改成正交后纯三维下界只剩 0.227；24-cell 任意顶点桥换投影必须重新扫描（XW −105° / YZ 70°）。
4. 无头浏览器 10 fps 下按时长走位不可靠：开发模式暴露 `window.__nexusPlayer = {x, z, w}`（仅 `import.meta.env.DEV`），Playwright 脚本改为按坐标反馈走位（`walkTo` / `slideTo`）。
5. w = −1 的东小室最初从 x 5.5 开始，玩家在走廊尽头 x ≈ 5.4 按 K 会被挡在 −0.5；小室前移到 x 4.8 与走廊充分重叠。
6. 桥的可见性在节点激活的**下一帧**刷新（会话内先算桥再算节点），测试里要多推一帧。

### 章节结构
`src/puzzle/chapters.ts` 把 `LEVELS` 按 `chapter` 分组为 `CHAPTERS`（标题、概念、结尾文案）。章末关完成 → 章节结算 → "下一章"或回菜单；主菜单可直接选章。`?level=N` 仍可直达任意关。

### 关卡数据格式

所有关卡以纯数据描述（`src/puzzle/levels.ts`），不含渲染代码：

```ts
interface LevelDef {
  id: string; title: string; hint: string[];
  platforms: AABB[];
  core: { position: Vec3; initialRotation: Rotation4D; allowedPlanes: Plane[];
          tilt?: Tilt; linked?: [Plane, Plane];          // 第二章
          projection?: { initial: ProjectionMode; switchable: boolean };   // 第四章
          polytope?: 'tesseract' | 'cell16' | 'cell24' };                  // 第五章
  bridges: BridgeDef[];
  nodes: NodeDef[];          // trigger: rotation | slice | reach(w?) | shape
  gates?: GateDef[];         // 第三章：节点满足即成路
  exit: { position: Vec3; radius: number; requires: string[]; w?: number };
  slice?: { enabled: boolean; initial: number; range: [number, number] };
  playerW?: { enabled: boolean; initial: number; range: [number, number]; sliceFollows?: boolean };  // 第六章；AABB 也带 w?
}
```

## 8. 三天开发计划（MVP）

每天结束：类型检查 + 构建 + 测试通过 → 提交到 `main` → 打备份标签 `backup/dayN-<主题>`。

### Day 1 — 四维引擎
- 初始化 Vite + React + TS + Three.js + Vitest。
- `hypercube.ts` / `rotation4d.ts` / `projection4d.ts` / `slicing4d.ts` 及其单元测试。
- 深色背景、超立方体线框（BufferGeometry 动态更新）、OrbitControls。
- 调试 HUD：六平面角度 + 切片位置 + 重置。
- **验收**：16/32/24；零角不变；旋转保距；θ 后 −θ 复原；XW 变化时投影确实改变；切片在 w₀=±1 时为立方体；math 不依赖 Three.js。

### Day 2 — 可玩机制
- `PlayerController` + AABB 可行走系统 + 角色。
- `LevelDef` / `LevelManager` / `PuzzleRules`（桥接条件、300 ms、锁定）+ 测试，含"纯三维旋转无解"的网格扫描测试。
- 第一关 The Fold 完整可玩（提示、桥动画、传送门）。
- 第二关 Reassembly（节点 + 两阶段桥）。
- **验收**：不看代码，键鼠即可从起点走到第二关终点；快速重置不损坏状态。

### Day 3 — 第三关与打磨
- 第三关 The Slice：截面渲染、切片节点、ZW 桥、最终结算。
- 开始菜单、暂停、重试、关卡完成、下一关。
- 视觉：多层线框、发光、桥/传送门反馈；WebAudio 合成音效。
- resize、WebGL 失败兜底、dispose；修复全部 TS / 构建 / 运行时错误。
- 构建静态产物并部署（GitHub Pages，源为 `main`）。
- **验收**：三关连续可玩；控制台无错误；线上可访问。

## 10. 已知取舍与风险

| 项 | 说明 |
|---|---|
| 没有四维碰撞 | 可行走表面是设计好的 AABB，桥由规则开关。这是有意的；Day 6 章节会引入按 w 层分组的 AABB，仍不是通用四维物理。 |
| 投影是透视而非正交 | 透视能让内外立方体交换更直观；正交投影可作为 HUD 的小窗辅助视图，非必须。 |
| 旋转顺序固定 | 四维旋转不可交换；固定顺序保证关卡确定性，但意味着 HUD 上的角度不是"绝对姿态"。 |
| 第三关节点判定基于截面顶点位置 | 这是截面几何的真实结果，不是假数据；但判定区间是手工调过的。 |
| 性能 | 线框总顶点数 < 200，瓶颈只会在后处理；`B` 键可关闭 bloom。 |
| 后处理管线 | three r182 的 `EffectComposer + OutputPass` 会把 sRGB 编码两次（背景从 #05070f 抬到 #262e45）。改用 r182 内置的 `renderer.setEffects([bloom])`（需 `outputBufferType: HalfFloatType`），色彩空间由渲染器统一处理。 |
| 音频 | WebAudio 合成（无音频文件）：环境底噪、共振音高随接近度上升、旋转嗡鸣按平面变调、锁定/节点/传送门/通关音效。首次按键或点击"开始"后解锁。 |
